# VAULT PRINT STUDIO

此工作副本为 **0.2.5 本地增强版**，基于上游 0.2.4，新增当前模块待打印零件的 3MF 导出。本分支尚未合并到上游默认分支或部署到在线版。

## 导出当前模块的待打印 3MF

在“配置与打印”的打印清单上方点击 **导出待打印 3MF**，核对剩余零件及份数，在弹窗中选择 **按设备型号** 或 **按热床尺寸**。设备列表按系列分组，拓竹覆盖 A1 mini、A1、A2L、P1P、P1S、P2S、X1、X1 Carbon、X1E、X2D、H2S、H2D、H2D Pro、H2C、H3C 共 15 款机型；另保留 Ender-3 V3 SE、K1 Max 和 Voron 2.4 350 规格。选择后自动带入对应热床尺寸，Combo / AMS 套装与对应机型共用选项。按尺寸时可选 180×180、220×220、256×256、300×300、325×320、350×320、350×350 mm，也可自定义。选择喷嘴直径后点击 **生成并下载 3MF**。选择拓竹机型后，还需选择实际耗材；导出引用匹配的官方机型、耗材及喷嘴对应的标准工艺，由 Bambu Studio 从本机系统预设继承参数，不再写入 VAULT 未指定机型/耗材占位名称。其他品牌或只按尺寸导出时仍为基础排盘项目；H2D / H2D Pro 使用 325×320 mm 单喷嘴范围，H2C 使用 305×320 mm 单喷嘴范围，H2S 为 340×320 mm，A2L / H3C 为 330×320 mm，X2D 使用 256×256 mm 主喷嘴范围；不要把双喷嘴总范围当作每个喷嘴的可达范围。勾选 **记住设置** 后，在开始导出时保存选择方式、设备或尺寸、喷嘴及耗材到当前浏览器，下次打开自动恢复。取消勾选后再次导出会删除已保存的导出偏好，不影响模型和打印记录。

默认开启 **按颜色自动分盘**，导出一个 Bambu Studio 项目：同色零件自动排在一起，每盘预留 5 mm 边距、零件之间至少 5 mm。比较多种尺寸排序和空闲矩形填充方式，优先减少盘数；尺寸模式下保留原逐行布局作为候选；选择拓竹机型时额外避开系统预设的不可打印区域，并检查实际打印高度。允许热床平面内旋转 90°，不翻转、不缩放，保留原来的贴床面；单件旋转后仍超出所选热床时明确阻止导出。放不下则继续增加打印盘，最多 36 盘。一个 STL 内有多色组件时保持完整，同一颜色组合单独分盘。请在 Bambu Studio 中作为项目打开，以保留实际打印盘和配色；仅导入几何会放弃项目设置。

拓竹机型项目使用本机系统预设引用，并通过 `different_settings_to_system` 明确声明仅保留项目的排盘范围和颜色等覆盖项，让未写入的机器与材料参数从匹配的系统预设恢复。打印高度、喷嘴数量和不可打印区域来自对应机型预设，不嵌入机器 G-code 或外部预设文件。耗材选择应用于所有颜色；使用多种材质时请在 Bambu Studio 中逐色调整。打开前请确保 Bambu Studio 已安装对应系统预设；旧版本缺少新机型/材料预设时仍可能提示，不能通过屏蔽警告解决。仅按尺寸或其他品牌设备导出时没有足够信息确定拓竹预设，仍保留 VAULT 基础排盘项目（默认高度 256 mm），打开后选择自己的打印机、耗材和工艺。切片前核对支撑、边缘余量及实际材料冲刷量。只按矩形占地排盘，不做任意角度旋转或孔洞/内腔嵌套，也不保证全局最少盘数；不代表已完成切片或实物验证。

关闭自动分盘则导出通用彩色 3MF。Bambu Studio 2.8 对没有喷嘴设置的标准模型可能先提示“配置无效，仅加载几何数据”，随后打开标准颜色导入窗口；这是其配置校验路径，不表示网格损坏。颜色窗口用于将文件颜色匹配到耗材。默认的分盘项目格式会携带基础配置及颜色，不经过标准模型的颜色映射流程。

- 只取当前选中的模块，不受清单搜索或筛选影响。已完成的零件不导出；部分完成只补剩余数量。单件/成对文件切换时按剩余实体数换算完整 STL 份数，需多出实体时会提示。
- 缺少待打印模型、配置不完整或人工版本份数尚未确认时，列出原因并阻止生成，避免得到漏件的包。
- 3MF 含完整有效原始网格，不使用三维预览的简化网格。每份原 STL 中的多个零件保持整体；副本按数量实例化、分开并贴床，分盘时可平面内旋转 90°，保持原始尺度和贴床面。
- 导出保留当前模块的默认配色和自定义配色，包括不同副本及同一 STL 内组件的独立颜色；实际 AMS 槽位仍需自行确认。多组件分别配色需要可靠匹配原网格分区，无法确认或超过 100 万有效三角面时会明确停止，可改用统一配色后导出。Bambu Studio 项目最多支持 32 种颜色。
- 原 STL 中同一三角面存在完全相同顶点时，该面面积为零，导出时跳过并在结果和包内清单记录数量；不改原文件，不做容差合并或常规减面。单模型限制 400 万唯一顶点，ZIP 输出限制 512 MiB，超出时明确停止。
- STL 不自带单位，按毫米解释坐标。导入切片软件后核对尺寸、打印盘、朝向和支撑，再进行切片；通用 3MF 不包含打印机、材料或层高设置，两种格式均不含 G-code。
- 生成在本机后台执行，支持取消；下载不会修改已打印份数。模型不会上传。

Windows 本地入口安装方式见 `tools/local-launch/LOCAL-LAUNCH.txt`。本地增强版固定使用 `http://127.0.0.1:5187/`；在线版的进度属于另一网址，需先在旧页面“导出进度”，再在本地增强版“恢复进度”并重新选择模型目录。

本地 STL 打印工作台：导入你拥有的模型，配置模块、查看三维装配关系，并逐件记录打印进度。黑橙色界面以模型舞台为中心，提供配置与打印、组合、零件库和装配手册四个工作区。

这是独立开发的工具，与 USSA Design 无隶属或背书关系。使用前需要自行合法取得对应 STL 文件；可通过 [USSA Design 官方产品页](https://www.ussadesign.com/products/vault)了解原项目。

## 在线使用

[打开 VAULT Print Studio](https://six111211.github.io/vault-print-studio/)。首次打开请选择自己购买的模型目录，检查匹配结果后进入工作台。模型只在浏览器本地读取，不会上传到 GitHub 或服务器；本站不提供模型下载包。

## 本地运行

### Docker 运行

安装并启动 Docker 后，在项目根目录执行：

```sh
docker compose up -d --build
```

打开 `http://127.0.0.1:5187/`。容器使用 Node.js 24 构建，再由 Nginx 提供静态文件；端口仅绑定本机。模型通过浏览器选择，不需要挂载进容器。进度保存在浏览器中，请保持相同浏览器和访问地址。

使用 `docker compose ps` 查看运行状态，`docker compose logs` 查看日志，`docker compose down` 停止服务。源码更新后重新执行上述构建启动命令。

### GitHub 自动构建镜像

`main` 分支 push 后，`Publish Docker` 工作流先运行测试与发布审计，再将 AMD64 / ARM64 镜像推送到 `ghcr.io/<仓库所有者>/vault-print-studio`。也可在 Actions 页面手动触发。使用内置 `GITHUB_TOKEN`，无需配置 Docker Hub 密钥。

当前仓库镜像为 `ghcr.io/mlch911/vault-print-studio:latest`，每次构建另有 `sha-<完整提交 SHA>` 标签，便于固定版本。运行已发布镜像：

```sh
docker run -d --name vault-print-studio --restart unless-stopped \
  -p 127.0.0.1:5187:80 ghcr.io/mlch911/vault-print-studio:latest
```

首次发布的 GHCR 包可能默认为私有；匿名拉取需要在 GitHub 包设置中将可见性设为 Public，私有包则需先登录 GHCR。

### Node.js 运行

需要 Node.js 24、npm，以及支持 WebGL、WebCrypto、Web Worker 和本地文件选择的现代浏览器。在项目根目录执行：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址，默认是 `http://127.0.0.1:5173`。通过本地 HTTP 服务运行；直接双击 HTML 文件不能可靠加载模块和 Worker。首次安装依赖需要访问 npm，应用使用时不依赖远程字体、模型或图片服务。

1. 选择模型总文件夹（包含子目录），也可将文件夹拖入导入区，或多选 STL。支持的浏览器优先调用原生只读目录选择，Safari 等使用普通目录入口；读取为空、权限拒绝或某个子目录失败会提示，不覆盖当前模型。未导入模型时，工作台保持锁定。
2. 在模型管理中检查匹配、缺失和冲突项。英文、中文或改名后的目录都可以导入；已知版本优先按文件签名匹配。
3. 在配置页左上选择组合方案，下方模型卡片只展示该方案的模块；点击卡片切换当前模块。独立模块单独收纳，可使用“删除当前模块”移出清单，“撤销上次删除”恢复原配置和打印记录，也可点击“多选”，勾选卡片或全选后批量删除；“撤销本次删除”会将本次整组按原顺序恢复，包含配置、配色和打印记录。刷新后仍可撤销最近一次单个或批量删除；不会清除已导入 STL。卡片显示规格、真实模型缩略图和打印进度，全部完成后显示绿色勾选，可用“下一个待打印”继续。完成或撤销单个零件不会自动跳走。
4. 明确点击“下载 STL”取得所选原文件，再交给切片软件。模型选择本身不会下载文件。
5. 无需先下载，即可标记完成份数。完成卡片变灰划线，对应三维零件淡化；撤销后恢复。下载与打印分别记录。切换单件／成对文件版本时按实体数量保留已完成进度，不足一整份的部分会单独提示。
6. 在组合工作台选择类型、宽度布局、深度和层高。S＋S、S＋M 的左右列可以分别选择模块类型、外框层高，并在任一列向上添加；点击模型或列卡片只在原位选中与编辑，点击“完成组合”才进入打印队列。删除模块或整组不会删除源模型文件或其他模块的打印记录。
7. 零件库按当前配置或指定规格列出必需配件，勾选后包含兼容选配；整库浏览保留为独立范围。
8. 装配手册内置系统使用、抽屉装配、翻盖箱装配、扩展改装、安装固定共 5 组中英对照 PDF，选择章节即可双栏阅读、同步翻页。也可临时换成本地 PDF。中文为非官方译文，术语或装配疑义请对照英文原文。

### 一个外框里的多个抽屉

配置页将“外框层高”和“框内抽屉”分开设置。S/M/L 的 2F 框可以装两个 1F 抽屉；4F 框支持两个 2F、四个 1F，或 2F 与两个 1F 的不同顺序。列表按从下到上显示，也可明确留出顶部空位。XL 仍限源目录提供的 1F 规格，不缩放或生成不存在的模型。

外壳、底部模块锁扣和顶盖只计一套；盒、面板、导轨、止挡、钥匙与弹簧等按内部抽屉数量配齐。同文件汇总打印份数；成对实体仍按完整 STL 文件计数，打印记录与配色保留。内部安装位置使用实测 48 mm 槽阵列，装配、爆炸、平铺和抽拉预览均使用原模型。

例如左右同高、左边两个浅抽屉右边一个深抽屉，可选择两个 S 系列 2F 外框，左框内部设为“1F＋1F”，右框保持“2F”。两个独立 1F 外框叠放与一个 2F 外框在当前源接合基准下存在约 4.2 mm 上沿差异：工具保留真实尺寸并提示，不允许在不齐的两列上跨列悬空叠放。外部落座、卡止及打印公差仍以原手册和实际零件为准。

浏览器通过你主动选择的 `File` 对象读取模型，没有文件上传接口。首次导入成功后，会自动把模型、目录路径及匹配结果保存在当前浏览器；看到“已在本机保存”后，下次使用相同浏览器、相同网址和端口打开，会直接恢复并进入工作台，无需重新选择文件夹或重复扫描整套 STL。后续进度、配色和人工匹配更新单独保存元数据，不重复写入大型模型文件。内置目录发生变化或旧缓存没有匹配快照时，会自动从已保存的本地文件重新检查，无需再次选目录。保存失败会明确提示暂勿关闭页面。普通首次使用或旧版本未保存过模型时仍需选择一次目录；“清除模型”会移除恢复缓存。不同浏览器、不同网址/端口、隐私模式或清理网站数据可能需要重新导入。导出的进度 JSON 只包含配置、配色和进度，不包含 STL；请按需导出备份。工具内更新仍会先安全保存模型和最新进度，再允许刷新或获取新版。

### 按颜色整体修改配色

在“配置与打印”的模型工具栏点击配色图标，无需先选中组件。展开“按颜色整体修改”，可看到当前模块使用的颜色及各自的组件数量；默认配色通常有三种。点击某行色块，或直接输入 `#RRGGBB` 并按 Enter / 离开输入框，可统一替换该颜色对应的全部组件，包括已打印组件。替换为已有颜色后会自动合并颜色分组，仅作用于当前模块。

“单个组件配色”保留原有逐件修改方式：先点击三维模型中的组件，再选择色块或自定义颜色。整体与逐件修改均保存到现有配色记录，刷新、导出/恢复进度、模块缩略图、组合预览和待打印 3MF 使用相同配色；不会改变打印份数。已打印组件仍按原规则淡化显示，其底色会随配色一起更新。

## 覆盖范围

规则覆盖抽屉（drawer）、翻盖箱（sustainer）和以下 14 类改装方案：推车、底座、轮组、移动底座、脚轮底座、支脚、背板、模块连接件、底座连接件、伸缩提手、固定提手、洞洞板附件、壁挂和桌下安装。不同系列、尺寸和选配项有各自约束；有待确认的份数、五金规格或缺失文件会影响清单完整性。

装配、爆炸和平铺采用可中断的平滑过渡，连续切换从当前位置接续；爆炸预览按当前视图分开零件，组合增层保持视角。开启系统“减少动态效果”时会尊重该偏好。

三维预览保持导入几何的原始尺度，通过刚体变换展示装配、开合和爆炸关系；下载保留用户原文件字节。STL 本身不声明长度单位，切片软件的单位设置仍需自行核对。装配位置用于可视化，未经过实物配合、干涉、承载或制造公差验证，不能据此认定物理兼容性。工具不执行切片，也不控制打印机。

## 文件识别与版本差异

仓库包含 733 条事实性目录记录：名称、ID、原相对路径、文件大小、包围盒、三角形数量、表面积和不可逆匹配签名。它不包含模型或预览网格；界面缩略图由当前用户导入的文件在本地生成。内置手册单独位于 `public/manuals/`，不属于模型目录元数据。装配辅助表只保存少量方向和坐标边界，没有顶点、面或三角形成员列表。

自动匹配以内容为依据，不要求英文、中文或固定目录名：

1. **完整文件签名**：按 1 MiB 分块对所有文件字节计算 SHA-256，再对版本标识、长度和有序分块摘要计算 SHA-256。已收录的文件可快速匹配；不是仅检查文件头尾。
2. **完整几何签名**：文件字节发生变化时，流式读取全部三角面，以 Float32 顶点坐标生成顺序无关的签名。忽略文件头、法线、属性字段、面顺序和面内顶点顺序，支持文本和二进制 STL 的等价导出。坐标、尺寸、朝向和重复面的数量保持区别，不会缩放模型。
3. **已收录的不同版本**：使用各版本的完整内容签名，并记录每份 STL 的实体数量。成对滑轨与单件滑轨自动采用不同打印份数。未确认用途或实体构成的文件仍需人工核对。
4. **未知几何版本**：只有外部尺寸相近不能证明同一零件；这类文件列为待确认。完全未知文件可搜索并人工指定零件，随后需要确认当前模块的打印份数，避免将“一份含两个零件”误当成“两份文件”。人工关联的版本不会套用参考版本的装配位置。

几何签名 `f32-multiset-v1` 使用八路 32 位三角面混合、256 位多重集合累加及 SHA-256，用于正常模型版本的匹配，不是对抗性完整性证明，也不是授权证明。重新三角化、修补、平移或旋转过的文件可能需要人工确认；名称只用于候选提示，不决定自动匹配。旧的头尾签名保留为兼容元数据，当前发布目录不使用它作为自动匹配依据。

导入器支持二进制和 ASCII STL，扩展名不区分大小写。单文件默认上限为 512 MiB，超限或读取失败只跳过该文件。完整内容检查以不超过 1 MiB 的切片进行；大型目录需要读取全部模型，界面显示当前文件和进度。超过百万三角面的二进制模型使用 0.12 mm 网格聚类生成预览，原始文件和下载字节不变。设备可用内存仍会限制大型模型预览。

**目录选错时**：`__MACOSX` 中的 `._xxx.stl` 通常是很小的 AppleDouble 附属文件，不含模型；工具会按文件内容跳过并提示选择模型主目录。只有说明书的备份目录不能提供模型。ZIP/RAR/7z 请先解压，再选择真正包含 STL 的目录。

本机安装 Bambu Studio 时，可设置 `BAMBU_STUDIO_CLI` 为其可执行文件路径，再执行 `node --test tests/three-mf-export.test.mjs`。 另设置 `BAMBU_STUDIO_PROFILES` 为 Bambu Studio 的 `profiles` 目录，可执行 `node --test tests/bambu-presets.test.mjs`，验证引用名称在官方系统预设中存在且与对应机型兼容。这会使用程序生成的测试网格进行原生导入/重新导出，验证实际盘数、各盘份数、颜色槽位和多色组件的逐面配色；未设置该变量时跳过原生程序验证。

官方预设引用表仅保存预设名称、兼容关系及机型能力数据，当前依据 Bambu Studio 02.09.01.70 生成；不包含机型 G-code。更新 Bambu Studio 后可重新生成：

```sh
node scripts/generate-bambu-preset-references.mjs --profiles-dir "<Bambu Studio profiles 目录>" --studio-version 02.09.01.70
```

构建输出位于 `dist/`，Vite 使用相对资源路径 `base: './'`，可部署在站点根路径或 GitHub Pages 仓库子路径。使用 `npm run preview` 在本地检查构建结果。

分发静态文件时，随构建结果保留许可证及第三方声明：

```sh
node --input-type=module -e "import {copyFileSync} from 'node:fs'; for (const name of ['LICENSE', 'THIRD_PARTY_NOTICES.md']) copyFileSync(name, 'dist/' + name)"
npm run audit:release -- --require-dist
```

发布审计默认扫描 Git 跟踪文件；在没有 Git 元数据的源码目录中，只扫描 `.github`、`scripts`、`src`、`tests` 和列明的根目录项目文件。存在 `dist/` 时也会扫描它；`--require-dist` 额外要求完整构建和随附许可证。内置手册仅允许清单列出的 10 份 PDF，源码及静态产物均校验文件长度与完整 SHA-256；其他本地目录不属于发布范围。

审计拒绝模型、独立图片、未列入清单的文档、压缩包等资产文件，检查 JSON 元数据结构、几何载荷、三角形选择列表、超长编码内容、常见凭据及本机绝对路径。构建代码使用有限的文本启发式，以避免误报 Three.js 的正常运行时代码。这是发布内容检查，不是任意混淆载荷检测器、授权验证器或安全保证。

## GitHub Pages

仓库提供两个工作流：

- `check.yml`：push、pull request 或手动触发，运行 Node.js 24、`npm ci`、测试、构建和发布审计。
- `pages.yml`：推送 `main` 或手动 `workflow_dispatch` 触发。构建、测试、审计完成后，仅上传并部署 `dist/`，包含许可证文件。

在仓库 Settings → Pages 中选择 **GitHub Actions** 作为发布来源，然后在 Actions 中手动运行 **Publish Pages**。部署任务使用 `github-pages` 环境，并单独声明 Pages 写入和 OIDC 权限；普通检查工作流没有发布权限。配置方法见 [GitHub Pages 自定义工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。仓库内容、Pages 启用和实际发布由维护者自行管理；这些文件不会自动创建远程仓库或发布 npm 包。每次部署生成 `version.json`，记录版本、Git 提交和发布时间；工具自动检查公开版本信息，每六小时最多自动检查一次，也可在“更新”中手动检查或关闭自动检查。检查本身不刷新页面、不改模型或打印状态。网页更新前在本机保存恢复数据；本地运行版保存后提供新版源码下载入口，由用户替换程序并保持原端口启动。
